## 2. 2일 차와 3일 차 사이의 집계 규칙 변경

과제 7 필수 조건인 **"2일 차와 3일 차 사이에서 집계 규칙을 1개 변경하고 이유를 기록할 것"**을 준수하여 아래와 같이 규칙을 개정했습니다.

### (1) 변경 내용 비교
* **기존 규칙 (1~2일 차 적용)**:
  - 할 일을 끝마치면 지연 여부나 시간 격차와 상관없이 `status === 'DONE'`이면 모두 **"정상 완료"**로 일괄 집계함.
* **개정 규칙 (3~5일 차 적용)**:
  - 할 일을 완료했더라도, **예상 시간 대비 실제 소요 시간이 0.5시간(30분) 이상 초과된 경우**는 성과 지표에서 단순 완료가 아닌 **"지연 완료(시간 초과)"**로 별도 분류하여 회고(See) 목록에 등록함.

### (2) 규칙 변경 사유
- 1~2일 차 실사용 결과, 완료 여부만 체크하다 보니 예상 시간 산정의 오류나 비효율적인 작업 습관(병목 현상)이 데이터상에 드러나지 않았습니다.
- 계획(Plan)과 실행(Do) 사이의 정확한 피드백 루프를 만들고, 다음 계획 시 예상 시간을 더 보수적으로 잡거나 장애 요인을 사전 제거하기 위해 3일 차부터 규칙을 개편했습니다.

## 3. 손 계산(수기) vs 화면 집계값 검산 일치 확인

화면에 표시되는 합계/평균값이 실제 데이터의 산술 합계와 정확히 일치하는지 검산하였습니다.

| 항목 | 수기 직접 계산 (손 계산) | 화면(UI) 집계 표시값 | 일치 여부 |
| :--- | :---: | :---: | :---: |
| **총 등록된 할 일 수** | 10건 | 10 | **일치 (PASS)** |
| **완료된 할 일 수** | 10건 | 10 | **일치 (PASS)** |
| **총 예상 소요 시간** | 2.0 + 1.5 + 2.0 + 1.5 + 3.0 + 2.0 + 2.5 + 1.5 + 2.0 + 1.5 = **19.5h** | 19.5h | **일치 (PASS)** |
| **총 실제 소요 시간** | 2.5 + 1.5 + 2.0 + 2.0 + 4.0 + 2.0 + 2.5 + 1.5 + 2.0 + 1.5 = **21.5h** | 21.5h | **일치 (PASS)** |
| **시간 격차 (실제 - 예상)**| 21.5h - 19.5h = **+2.0h** | +2.0h | **일치 (PASS)** |
| **초과 지연 건수 (0.5h 이상)**| Day 1(1번), Day 2(4번), Day 3(5번) = **3건** | 3건 | **일치 (PASS)** |

- **검산 결론**: 브라우저의 JavaScript 연산 결과와 수기 산출 결과가 100% 일치함을 확인하였습니다.
